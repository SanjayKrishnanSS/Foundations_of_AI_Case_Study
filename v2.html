Method overview

Iterative Deepening Search repeatedly runs depth-limited DFS. After each unsuccessful pass, it increases the depth limit by one and searches again from the root.

  1. Begin with depth limit 0.
  2. Run depth-first search, but do not expand nodes at the limit.
  3. If the goal is not found, increase the limit.
  4. Restart from the root and repeat until the goal is found or the maximum limit is reached.
limit = 0, 1, 2, 3, ...

Key idea: shallow nodes are revisited, but most nodes in a large tree are near the deepest level, so this repeated work is often acceptable.

Complexity and properties
Technical reference

    

      
Time complexity
O(bd)
For branching factor b and shallowest goal depth d. Nodes near the bottom dominate the total work.

      
Space complexity
O(bd)
Depth-first traversal stores the current path and a limited set of unexplored siblings.

      
Completeness
Yes*
Complete when the branching factor is finite and a solution exists at a finite depth.

    

    

      
Advantages

      
  • Finds a shallowest-depth solution when all step costs are equal.
  • Uses much less memory than breadth-first search on large trees.
  • Does not require knowing the solution depth in advance.

      
Limitations

      
  • Re-expands upper-level nodes in every iteration.
  • Not optimal when action costs differ; use uniform-cost search for varying costs.
  • Depth limits need careful handling in graphs with cycles (use path-cycle checking or a suitable graph-search variant).

    

    
Notation: b = branching factor; d = depth of the shallowest goal. Some references express the space bound as O(d) for a tree with constant branching factor; O(bd) is the common general form.
